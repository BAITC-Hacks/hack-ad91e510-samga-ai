# Проверяемая аналитика Samga

Рабочий этап симулятора: ручной выбор пяти мер, серверный расчёт, сравнение гипотез, полный поиск и помощник с проверяемыми фактами. Карта схематическая.

## Запуск

Нужен Node.js 24+. Внешние npm-пакеты не требуются.

```sh
node backend/server.mjs
```

Откройте http://127.0.0.1:4197. По умолчанию режим demo: расчёт, поиск, сравнение, источники и шаблонный разбор работают без сети. Свободный диалог не имитируется. Остановка — Ctrl+C.

Для живого AI команда подключит хакатонный доступ позже. Существующий backend читает серверные AI_MODE, OPENAI_API_KEY и OPENAI_MODEL; контракт и интеграция готовы, реальный вызов пока не проверен. Не передавать ключ в браузер или Git.

## Проверки

```sh
node --test docs/brief-analysis/test/model.test.mjs backend/test/api.test.mjs analytics/test/*.test.mjs
```

На этом этапе проходят 46 тестов. Проверены контрольные формулы, перебор 694395 планов, ограничения, подмена данных клиента, неизвестные факты, неверная классификация факта, AI-отказы/таймауты и HTTP-интеграция. Транспорт AI в тестах подменяется; это не проверка качества реальной модели.

В браузере Edge проверены экраны 1440/1024/390, каталог, недопустимый план, поиск со школой за 80, применение, сравнение, источники и отсутствие ключа.

## Что обеспечивает точность

1. Единственная формула: docs/brief-analysis/dist/model.mjs. Новые компоненты её вызывают, а не создают свою версию.
2. Только ID и районы определяют результат; стоимость и эффекты берутся из серверного каталога.
3. Перед анализом результат пересчитывается. Подмена score, baseline, районных значений или scenarioId вызывает SCENARIO_MISMATCH до обращения к AI.
4. scenarioId зависит от нормализованного выбора, версии модели и данных. Порядок мер не меняет ID. Это идентификатор содержания, не подпись и не авторизация.
5. AI выбирает ID фактов. Сервер проверяет ID и пригодность факта как улучшения/риска, затем сам формирует фактический текст. Свободный числовой прогноз не принимается.
6. Запрос пользователя к помощнику преобразуется в типизированное намерение: анализ, сравнение, поиск, источники или уточнение. Выполняется только разрешённый инструмент.
7. Найденный план требует явного применения. Интерпретацию цели и ограничений пользователь видит.
8. Интерфейс игнорирует результаты предыдущей версии выбора. Полная точность понимания естественного языка не гарантируется; живые примеры нужно оценить после подключения модели.

## API для frontend

Все POST принимают JSON. GET /api/catalog возвращает районы, 14 мер, показатели и описание модели.

| Маршрут | Тело | Результат |
|---|---|---|
| POST /api/simulate | {choices} | Совместимый контракт v1: scenarioId, choices, baseline, result |
| POST /api/facts | {choices, years?:2} | Проверенный разбор mode=verified и факты |
| POST /api/analyze | Полный ответ simulate | AI-выбор фактов; предварительный пересчёт |
| POST /api/compare | {left:choices, right:choices} | Оба результата, дельты, добавленные/удалённые меры, изменения 50 показателей |
| POST /api/search | Ограничения ниже | Полный поиск, количество планов, лучший сценарий либо infeasible |
| POST /api/evidence | {measureIds:["M7","M8"]} | Карточки первоисточников и пробелы |
| POST /api/assistant | {question,choices,comparisonChoices?} | Проверяемый результат выбранного инструмента, interpretedIntent, scenarioId |
| GET /api/health | — | Режим и наличие конфигурации, не проверка доступа к API |

Пример поиска:

```json
{"objective":"cost","maxBudget":100,"criticalLimit":0,"required":[{"id":"M7","district":"Нура"}],"excluded":[]}
```

Цели: score (максимум общего Score), cost (минимальные расходы), weakest (максимум минимального районного балла), air (максимум E2 с весами населения). При равенстве используются дополнительные критерии: score/cost согласно analytics/optimizer.mjs. Поиск точный только в конечной модели DOCX. Без criticalLimit:0 минимизация стоимости не обещает убрать критические показатели.

Обязательная районная мера должна содержать district; городская — только id. Модель не добавляет ежегодное пополнение бюджета.

Пример {id:"M12"} — городская мера. {id:"M7",district:"Нура"} — районная.

Коды ошибок: 422 INVALID_SCENARIO / INVALID_CONSTRAINTS / SCENARIO_MISMATCH / HORIZON_UNSUPPORTED; 429 SEARCH_BUSY; 504 SEARCH_TIMEOUT. AI-коды описаны в backend/README.md. Старые scenarioId из прежнего backend нужно получить повторным simulate.

## Мировой опыт и прогнозы

Восемь карточек WHO, World Bank, OECD покрывают контекст всех пяти направлений. У каждой есть ссылка, дата проверки, ограничения применимости и usedAsCoefficient=false. Карточки не доказывают численные эффекты для Астаны. Для M2/M9/M10 в текущей базе нет сопоставленного внешнего обоснования; API сообщает это явно.

Проверены публичные описания/страницы источников; систематический обзор литературы, проверка всех исходных исследований и местная калибровка не выполнены. Отсутствие записи не означает отсутствие исследований.

Горизонт модели — 8 кварталов. Формула DOCX не задаёт годовую траекторию. Запросы на 1/5/10 лет дают HORIZON_UNSUPPORTED, а не выдуманную экстраполяцию. Для полноценного временного симулятора нужны местные ряды населения, спроса, сроков, затрат на эксплуатацию и эффектов, калибровка и проверка на отложенных периодах. Численные «мировые коэффициенты» в модель не импортированы.

## Устройство

- scenarios.mjs — проверка ввода, нормализация, пересчёт, идентификатор и сравнение.
- optimizer.mjs — исчерпывающий поиск с ограничениями; каждый вариант оценивается общей формулой.
- search.mjs / search-worker.mjs — worker для поиска, лимит 2 задач, дедлайн 30 секунд, ограниченный кеш.
- evidence.mjs — первоисточники и ограничения.
- grounding.mjs — проверка факт-ID и формирование текста.
- backend/assistant.mjs — интерпретация вопроса в разрешённое действие.
- public/ — автономный рабочий интерфейс через существующий backend.

Сервер слушает loopback. Для публичной публикации нужны авторизация, квоты, ограничения пользователей и конфигурация инфраструктуры. Текущий CORS не является авторизацией.

## Сценарий защиты

1. Пример организатора: 95 единиц, Score 56.54307.
2. Цель «Минимальные расходы», без критических показателей: 66 единиц.
3. Закрепить школу в Нуре: 80 единиц; поиск проверяет последствия вместо обещания AI.
4. Применить и сравнить, показать снижение отдельных показателей при замене.
5. Открыть «Объяснить расчёт» и «Основания».
6. Попробовать 10 лет: интерфейс объясняет отсутствие проверенной модели.
