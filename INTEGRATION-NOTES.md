# Исторический журнал интеграционной версии SAMGA AI

Это сохранённая инструкция предыдущего интеграционного этапа. Для текущего запуска и статуса используйте [основной README](README.md).

Выберите пять городских мер, распределите бюджет 100 и сравните последствия для
пяти районов Астаны. Основной интерфейс — выбранная командой карта **ASTANA / City Lab**.
Расчёт выполняется сервером по датасету организатора, AI объясняет готовый результат.

**Проверено локально:** самостоятельный выбор, ограничения, серверный расчёт,
сравнение показателей и полный браузерный путь. **Живой AI ещё не проверен:**
без командного API-доступа сервер честно показывает режим «Без LLM».
Этот снимок сам по себе не подтверждает публикацию или принятие конкурсной версии.

## Запуск для эксперта

Нужен **Node.js 24+** и современный браузер. Установка npm/pip-пакетов не требуется.
Распакуйте весь переданный ZIP или используйте корень конкурсного репозитория:

```sh
node backend/server.mjs
```

Откройте **http://127.0.0.1:4197/**. Один сервер обслуживает и сайт, и API.
Остановка — Ctrl+C. Сервер слушает только 127.0.0.1.
Если порт занят, задайте другой через переменную окружения PORT.

Также доступны START-MAC.command, START-WINDOWS.bat и
`python3 start-demo.py` (последний дополнительно требует Python 3 и выбирает
свободный порт). Подробности — [START-HERE.md](START-HERE.md).
file:// и отдельный Python HTTP-сервер для основного продукта не подходят: нужен API.

**Учётная запись эксперту не нужна.** Вход, личный ChatGPT и аккаунт участника
в приложении не запрашиваются. В ZIP есть исходники и конкурсный датасет; доступ
к приватному GitHub для запуска ZIP не нужен. Для подложки карты нужны интернет
и WebGL; выбор мер, расчёт и таблицы не зависят от загрузки внешних тайлов.

## Проверить основной сценарий

1. В начале план пуст: 0 из 5 мер, расход 0, доступно 100.
2. Нажмите «Выбрать 5 мер». Для районной меры выберите один из пяти районов.
3. Для эталона организатора добавьте:

| Мера | Район | Цена |
|---|---|---:|
| M7 — школа и детсад | Нура | 24 |
| M8 — поликлиника | Нура | 20 |
| M10 — освещение и камеры | Нура | 12 |
| M12 — обращения жителей | весь город | 14 |
| M5 — чистое топливо | Сарыарка | 25 |

4. Нажмите «Рассчитать результат»: расход **95**, база **52.55768**, итог
   **56.54307**, критических показателей **2 → 0**. Округление только на экране;
   точное число раскрывается в «Как получен Score» и возвращается API.
5. Посмотрите пять районов и все десять показателей выбранного района,
   переключите «Сейчас / После решений» на карте.
6. Нажмите «Получить AI-объяснение». Режим ответа отображается явно;
   ошибка AI сохраняет числовой результат и позволяет повторить запрос.
7. Измените решения и повторите расчёт. Старые результаты и AI-ответы
   сбрасываются при изменении плана.
8. «Сравнить и сохранить отчёт» открывает [пакет для жюри](briefing/README.md):
   сравнение альтернатив, поиск с явными ограничениями, автономный HTML и JSON.
   Найденный план можно открыть на карте; перед применением он целиком проверяется.

Правила: ровно пять уникальных мер M1–M14, максимум две одного направления,
расход не более 100. M1/M3 несовместимы везде; M4/M7 и M5/M13 — в одном районе.
Сарайшык виден на карте без показателей и недоступен для назначения мер:
конкурсный датасет не содержит его значений.

## Живой AI через предусмотренный командой OpenAI API

Локально скопируйте backend/.env.example в backend/.env и заполните
AI_MODE=openai, OPENAI_API_KEY, OPENAI_MODEL (доступная команде модель
Responses API с поддержкой strict Structured Outputs). Не передавайте ключ в чат,
браузер, Git или ZIP. Запуск из корня:

```sh
node --env-file=backend/.env backend/server.mjs
```

Ключ остаётся на сервере. В OpenAI передаются синтетический сценарий и вычисленные
факты; LLM выбирает ID существенных фактов и следующий шаг. Сервер проверяет их
существование/смысл и формирует текст с точными числами. **LLM не рассчитывает Score.**
/api/analyze повторно рассчитывает сценарий и отвергает подменённые числа.
store:false, таймаут 20 секунд, без автоматических платных повторов.

GET /api/health сообщает режим и наличие конфигурации, но не доказывает доступ.
Живой пруф — успешный ответ /api/analyze с mode:"openai", тот же scenarioId
и отображённое объяснение в браузере. demo и тестовая заглушка таким пруфом не являются.
Эксперт использует настроенный командный сервер; личный аккаунт участника ему не нужен.
Подписка ChatGPT/Codex не заменяет API-ключ.

## Формула и исходные документы

```text
Score = 0.7 × D_avg + 0.3 × min(D_d) − N_crit
```

D_avg взвешен по доле населения; N_crit считает пары «район × показатель»
со значением строго ниже 40. Прямые эффекты умножаются на (8 − лаг) / 8,
синергии фиксированы, итоговые показатели ограничены 0–100.

[Оригинальный DOCX](docs/brief-analysis/dist/sources/dataset.docx) и
[оригинальный PDF](docs/brief-analysis/dist/sources/brief.pdf) входят в репозиторий.
Данные учебные, не официальная статистика или прогноз для реального города.

**Открытый вопрос организатору:** «Верно ли, что действуют правила DOCX:
пять разных мер, максимум две одного направления, и охват всех пяти направлений
не обязателен?» До ответа реализована модель DOCX. PDF формулирует требование
о пяти направлениях; это расхождение не объявлено решённым.

## Проверки

```sh
node --test docs/brief-analysis/test/model.test.mjs backend/test/*.test.mjs analytics/test/*.test.mjs frontend/test/*.test.mjs demos/astana-city/test/*.test.mjs briefing/test/*.test.mjs
node backend/demo.mjs
node scripts/jury-check.mjs
```

Первая команда — автоматические проверки без внешних пакетов; OpenAI transport в них
подменён. Вторая запускается при работающем сервере и явно выводит режим AI.
Проверка запускатора: `python3 -m unittest discover -s tests`.
Исторический frontend/test/browser.mjs требует необязательный Playwright;
он не входит в запуск продукта. Основной браузерный путь проверен отдельно.
Проверка jury-check выполняет детерминированные HTTP/API сценарии, без живого AI.
Сценарий показа и доказательства — [docs/jury/](docs/jury/EVIDENCE.md).
