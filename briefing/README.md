# Сравнение стратегий и итог решения

Дополнение к существующему симулятору. Использует исходную модель, существующий
исчерпывающий поиск и серверные API. Новых зависимостей и AI-запросов нет.

## Пользовательский путь

1. Открыть `/briefing/` в общем приложении.
2. Сравнить районные проекты в Есиле с примером школы/поликлиники в Нуре.
3. Указать цель, бюджет, необходимость убрать критические значения и школу в Нуре.
4. Выполнить поиск. Увидеть число проверенных и подходящих вариантов, результат,
   ухудшения и оставшиеся проблемы. Если решения нет, прежний план не заменяется.
5. Открыть найденный план на карте или сохранить автономный HTML и JSON.

`?plan=` принимает URI-encoded JSON выбора, например `{id:"M7",district:"Нура"}`.
Весь набор пересчитывается на сервере. Название плана не является доказательством
оптимальности; такое доказательство на экране появляется только после полного поиска.

## Подключение к существующему серверу

- GET `/briefing/` → `briefing/index.html`.
- GET `/briefing/app.mjs`, `/briefing/session.mjs`, `/briefing/style.css` → соответствующие файлы.
- POST `/api/brief`: разрешённые поля `choices`, `comparisonChoices`, `title`.
  Вызвать `buildBrief(input)` из `briefing/report.mjs`, вернуть
  `{brief, html: renderBriefHtml(brief)}`. Использовать существующий readJson/лимит
  тела/обработку ошибок сервера. Ошибки `INVALID_SCENARIO` → 422.
- Поиск — существующий POST `/api/search`; новые алгоритмы/формула не вводятся.
- Обратная ссылка на карту `/?plan=...` передаёт только выбор. Карта проверяет
  весь план перед применением; импорт не должен добавлять часть невалидного набора.

## Проверка

```sh
node --test briefing/test/*.test.mjs
node scripts/jury-check.mjs
```

Вторая команда запускает временный loopback backend в явном demo-режиме,
выполняет HTTP-проверки и останавливает его. Внешний AI не вызывается.

Проверка уже запущенной общей версии:

```sh
node scripts/jury-check.mjs --url http://127.0.0.1:4197
```

Только после настройки реального серверного доступа:

```sh
node scripts/jury-check.mjs --url http://127.0.0.1:4197 --live-ai
```

Последняя команда вызывает настоящую модель один раз. Результат `mode:demo`,
ошибка или неподтверждённый ответ не засчитываются. Ключи в отчёт не включаются.
Код завершения 0 без `--live-ai` доказывает только перечисленные детерминированные
API-проверки: поле `requiredAiVerified` при этом остаётся false.

## Что гарантирует экспорт

`buildBrief` получает только выбор, вызывает общий engine через `calculateScenario`,
сравнивает 50 показателей и раскладывает изменение Score на три слагаемых.
`renderBriefHtml` повторно строит расчёт из выбора, не доверяя числам переданного JSON.
Заголовок экранируется; в автономном HTML нет JavaScript и внешних ресурсов.
JSON сохраняет сценарий, версию, идентификатор и ограничения для воспроизведения.
Это пересчитанная записка, не подписанный документ и не результат живого AI.
